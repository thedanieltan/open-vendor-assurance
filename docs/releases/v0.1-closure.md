# OpenVA v0.1 closure note

OpenVA v0.1 is the closure point for the resolver-first product contract. The project is considered functionally complete for its current scope: a public-source, metadata-first vendor assurance reference resolver for human review sheets and agent-composed workflows.

## Locked contracts

### Human CSV review output

The human path is intentionally fixed and simple:

```text
Upload vendor list CSV
→ match indexed vendor records
→ return a review sheet with selected public source URLs
```

The human CSV contract avoids internal OpenVA diagnostics and advisory language. It does not expose match reasoning, source health states, candidate lists, live verification hints, or compliance conclusions.

The human CSV columns are:

```text
vendor_name
business_entity_name
domain
jurisdiction
registration_number
registered_address
matched_vendor_name
official_domain
trust_security_url
dpa_url
subprocessors_url
privacy_notice_url
status_page_url
```

Human export presets are deferred. If users later need narrower review views, those should be optional projections over the same stable base template, not new semantics.

### Agent enrichment result

The agent path is destination-neutral and schema-pinned. New agent, MCP, API, and SDK consumers should prefer:

```text
identity
source_references
```

Compatibility fields remain available for older adapters:

```text
match
sources
primary_source_by_type
source_urls_by_type
```

`identity` and `source_references` are first-class fields in `schemas/openva/agent-enrichment-result.schema.json`, not tolerated extension fields.

Agents own workspace access, user approval, and write-back. OpenVA only receives bounded vendor identities and returns public-source references from the loaded snapshot.

## Product boundary

OpenVA v0.1 does not:

- approve, score, rate, certify, monitor, or assess vendors;
- provide legal, compliance, procurement, audit, security, KYC, AML, sanctions, regulatory, or vendor-risk advice;
- live-fetch or verify URLs during browser-local CSV compilation;
- require access to a user's Google Drive, Microsoft 365, Notion, Jira, Slack, or internal workspace;
- treat a no-match or missing source URL as non-compliance.

OpenVA v0.1 does:

- resolve vendor identity against indexed public-source records;
- return selected public vendor assurance references;
- preserve a clean human CSV contract;
- expose a structured agent result contract;
- retain compatibility projections for existing consumers;
- keep the advisory boundary explicit.

## Non-blocking future work

The following work is intentionally deferred and should not block v0.1 closure:

- generated catalog/index migration from legacy `canonical_sources` aliases to preferred source-record vocabulary;
- later removal of compatibility fields after downstream consumers migrate;
- optional human export views if real users ask for narrower review sheets;
- live verification productization and hosted resolver operations;
- deeper catalog growth and source-maintenance automation.

## Closure rule

After this point, OpenVA should not grow new features unless there is concrete user or agent demand. Maintenance should focus on correctness, documentation clarity, public-source catalogue hygiene, and keeping the human and agent contracts stable.
