# OpenVA Doctrine

OpenVA is a public vendor assurance knowledge substrate.

It exists to preserve structured, factual metadata about public vendor-published assurance materials.

## Core doctrine

OpenVA is:

- public-source-only;
- metadata-first;
- factual and non-advisory;
- native-language-aware;
- provenance-driven;
- hash-friendly;
- exportable through universal packs;
- useful independently of any single downstream runtime.

## Boundary

OpenVA owns public-source factual metadata.

Downstream systems own private operational decisions.

OpenVA may record that a vendor publishes a public subprocessor page. It must not decide whether that vendor should be approved, rejected, considered low risk, treated as compliant, or mapped as satisfying an organization's obligation.

## Data authority versus runtime authority

OpenVA may be authoritative for its own public dataset records.

It is not authoritative for legal, compliance, procurement, audit, KYC, AML, security, or vendor-risk conclusions.

## Export posture

OpenVA should publish universal dataset packs and import-adapter primitives.

Consumers are responsible for mapping OpenVA records into their own systems, workflows, policies, and use cases.
