## Public launch blockers

Block public launch if any of these appear before cutover:

- failing required `validate / ...` checks on `main`;
- failing release-candidate workflow;
- generated `openva-pack.json`, `indexes/`, or `dist/` drift;
- pack/schema/profile incompatibility;
- tracked bytecode/cache artifacts;
- raw vendor document mirrors committed by default;
- private, gated, customer-specific, portal, NDA, SOC report, ISO certificate, or extracted full-text material;
- advisory wording or vendor approval/scoring claims;
- workflow permission escalation;
- issue templates, CODEOWNERS, SECURITY.md, or governance docs missing from the public launch path.

## Non-blocking launch backlog

Do not block v0.1.0 on these items alone:

- bot-protected public vendor pages;
- transient fetch failures;
- size-limited public pages;
- better source candidates not yet found;
- native-language summary improvements;
- catalog expansion backlog;
- source-refinement queue items that remain metadata-only and public-source-only.

## Manual cutover sequence

Recommended sequence:

1. Run the manual `release-candidate` workflow on `main`.
2. Download and inspect `release-artifacts.json`.
3. Run or review the latest `observe-report` output.
4. Confirm source-refinement queue contains no release blockers.
5. Confirm the required partitioned validation checks are green on `main`.
6. Decide whether to tag `v0.1.0` before or after public visibility.
7. Change repository visibility only through GitHub repository settings.
8. Publish a launch note that preserves the public-source-only, metadata-first, non-advisory boundary.

## Launch positioning

Use:

```text
OpenVA is a public-source-only, metadata-first registry of vendor-published assurance references.
```

Also use:

```text
OpenVA v0.1.0 is an infrastructure launch, not a completeness claim.

The initial catalog is a seed dataset. It is useful for testing importer
workflows, matching public vendor assurance references, and contributing
public-source metadata, but it should not be treated as complete vendor
assurance coverage.

OpenVA does not operate a public upload service or central hosted matching
service. HTTP access is available only through the optional self-hosted match
service. Users should keep private vendor inventories inside their own
environment.
```

Do not use:

```text
compliance database
legal document archive
vendor risk scoring system
certification authority
procurement recommendation engine
```
