# v0.1.0 Release Candidate Checklist

This checklist prepares OpenVA for a first public release candidate.

`v0.1.0` should be treated as a public launch baseline for OpenVA's metadata-first substrate, not as a claim that the vendor catalog is complete or that any vendor is approved, verified, compliant, secure, suitable, or recommended.

## Release identity

Expected identifiers:

```text
package version: 0.1.0
record schema_version: 0.1.0
profileId: openva.public-metadata.v1
schemaVersion: openva-export-pack.v1
packId: open-vendor-assurance
release tag: v0.1.0
```

## Release candidate scope

`v0.1.0` may include:

- public-source-only vendor metadata;
- generated indexes;
- `openva-pack.json`;
- OpenVA schemas;
- validation tooling;
- catalog batch tooling;
- observation dry-run tooling;
- conformance fixtures;
- governance and contribution docs;
- release and versioning docs;
- CI and branch-protection guidance.

`v0.1.0` must not include:

- raw vendor document mirrors by default;
- private or gated materials;
- authenticated trust-center materials;
- SOC reports from private portals;
- private ISO certificates;
- customer-specific or bespoke agreements;
- legal, compliance, procurement, security, KYC, AML, sanctions, regulatory, or vendor-risk advice;
- vendor approval, certification, ranking, recommendation, suitability, adequacy, or risk scoring claims.

## Manual release candidate workflow

Maintainers may run this manual GitHub Actions workflow before tagging:

```text
release-candidate
```

The workflow is read-only. It does not tag, publish a release, change repository visibility, write to `main`, create issues, create PRs, or mutate catalog records. It uploads `release-artifacts.json` as a workflow artifact when requested.

## Required release commands

Run the release smoke test from a clean working tree:

```bash
python -m tools.openva.release_smoke
```

The smoke test covers the required release checks. Maintainers may also run the underlying commands individually:

```bash
python -m tools.openva.validate build-indexes
python -m tools.openva.validate validate
pytest -q
python -m tools.openva.conformance fixtures/packs/minimal-valid
python -m tools.openva.conformance fixtures/packs/valid-bot-protected-observation
python -m tools.openva.release_artifacts build
python -m tools.openva.release_artifacts check
```

Then verify no generated files changed unexpectedly:

```bash
git diff --exit-code openva-pack.json indexes/
```

## Required workflow checks

Before tagging, confirm:

```text
validate / validate passes on main
catalog-pr-guard is available for Catalog: PRs
observe-dry-run remains manual-only
release-candidate passes when manually dispatched
```

## Manual review checklist

- [ ] README describes public-source-only, metadata-first scope.
- [ ] DISCLAIMER is present and consistent with README.
- [ ] CONTRIBUTING explains accepted and rejected materials.
- [ ] GOVERNANCE explains maintainer duties and human-review requirements.
- [ ] SECURITY explains private reporting and workflow boundaries.
- [ ] MAINTAINERS exists and is current.
- [ ] CODEOWNERS covers governance-sensitive paths.
- [ ] Issue templates route source corrections, catalog requests, boundary questions, bugs, docs, and out-of-scope requests.
- [ ] `docs/index.md` links major docs.
- [ ] `docs/public-launch-checklist.md` is current.
- [ ] `docs/versioning-policy.md` is current.
- [ ] `docs/release-policy.md` is current.
- [ ] `docs/release-checklist.md` is current.
- [ ] `docs/ci-and-branch-protection.md` is current.
- [ ] Consumer conformance fixtures are present and tested.
- [ ] Invalid conformance fixtures fail for expected reasons.
- [ ] Generated indexes and pack manifest are current.
- [ ] `release-artifacts.json` is generated for the release candidate or release asset.

## Branch protection before tag

Before tagging `v0.1.0`, confirm `main` protection expectations from:

```text
docs/ci-and-branch-protection.md
```

At minimum:

- require pull requests before merging;
- require `validate / validate`;
- restrict force pushes;
- restrict branch deletion;
- require conversation resolution;
- require CODEOWNERS review where available;
- prevent automation from merging directly to `main`.

## Release note draft

Suggested title:

```text
OpenVA v0.1.0 — public metadata substrate release candidate
```

Suggested summary:

```text
OpenVA v0.1.0 establishes a public-source-only, metadata-first substrate for vendor-published assurance references. It includes schemas, generated indexes, an export pack manifest, validation tooling, observation dry-run tooling, consumer conformance fixtures, catalog-agent guardrails, and public contribution governance.
```

Required limitation wording:

```text
OpenVA records are best-effort metadata about public vendor-published sources. They may be incomplete, stale, incorrect, superseded, jurisdictionally limited, product-specific, or based on public standard terms that do not reflect negotiated or bespoke customer agreements. OpenVA does not provide legal, compliance, procurement, audit, security, privacy, KYC, AML, sanctions, regulatory, or vendor-risk advice.
```

## Tagging

Only after all checks pass:

```bash
git tag v0.1.0
git push origin v0.1.0
```

Do not tag from a branch that is behind `main`.
