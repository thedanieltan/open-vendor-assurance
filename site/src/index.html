FAQ

Direct answers about OpenVA.

What the product provides, what it deliberately does not, and how to work with its output. Vendor-specific facts remain linked to the original vendor-published source URLs.

What is OpenVA?

OpenVA is an open-source catalog and resolver of public vendor-published assurance source URLs. It records factual locator metadata for human and agent users — vendor identity metadata, supported source types, vendor-published URLs, current resolved URLs where observed, source collection dates, snapshot identity, and machine-readable exports.

Which source types does OpenVA support?

OpenVA supports fifteen source types, including data processing addenda, privacy notices, subprocessor lists, security pages, trust centers, compliance pages, terms, transparency reports, service status pages, and related public sources.

Does OpenVA assess, approve, or score vendors?

No. OpenVA does not certify, approve, endorse, rank, recommend, or determine whether a vendor is compliant, secure, suitable, or low risk. It does not provide legal advice, compliance decisions, procurement recommendations, security conclusions, or private evidence.

Are vendor source URLs permanent?

No. Vendors can move, redirect, replace, or remove their pages. OpenVA records observed destinations and repairs accepted source records — through the catalog governance process — when an authoritative public location changes.

Does a vendor CSV leave the browser?

No. The public resolver processes the selected CSV in browser memory. OpenVA has no upload endpoint, account system, or server-side workspace for the file.

How should an OpenVA result be cited?

Cite the original vendor-published URL for the underlying source. Use the OpenVA vendor page or JSON export to cite the catalog snapshot, source type, observation metadata, and provenance.
