# OpenVA Static Site

The OpenVA static site is the public browser surface for the current accepted catalog on `main`.

It is a **static OpenVA contract and community-index browser**. It is not a hosted advisory service, private evidence workspace, or formal release portal.

## Public surfaces

```text
Static site
Resolver contract documentation
Community index browser
Local resolver / CLI / MCP entry point
Result-pack preview
Configurable source-pack builder
Browser-local resolver
Source pack preview
Export Source Pack
```

The compiled static distribution is generated by:

```bash
python site/build.py --out site/dist
```

The build emits, among other files:

```text
data/meta.json
data/vendor-search.min.json
data/vendors/{vendor_id}.json
public/openva-agent-index.json
.well-known/openva.json
robots.txt
sitemap.xml
llms.txt
```

## Continuous publication

There is no tag-driven or formal catalog-release lifecycle.

```text
accepted change
→ merge to main
→ validate records and rebuild indexes
→ build site/dist
→ deploy GitHub Pages
```

The source commit SHA is the catalog snapshot identity. Generated timestamps and digests remain separate provenance fields. Consumers that need a fixed state should pin the exact commit SHA or verified digest.

## Browser-local boundary

Private CSV input is processed in browser memory only. It is not written to `localStorage`, `sessionStorage`, a server, or a database.

The static site has:

- no backend, database, account system, upload endpoint;
- no live verification job;
- no live discovery job;
- no hosted resolver worker;
- no server-side workspace persistence.

The community index is hint-only for local matching. Where used, consumer-side live verification belongs to the consumer or a separately operated resolver—not the static page.

The output remains public metadata and source-reference facts. Result-pack provenance fields distinguish candidate and verification basis, including fields such as:

```text
openva_{source_type}_candidate_basis
openva_{source_type}_verification_basis
```

## Publication files

The homepage and generated discovery files derive OpenVA-owned URLs from `config/publication.yaml`. The configuration contains the canonical site URL, repository URL, and agent-index path. It does not contain a GitHub Release URL.

`site/build.py` wraps the preserved builder implementation in `site/build_core.py` and removes retired release metadata from generated output. The resulting metadata identifies:

- source commit SHA;
- catalog generation timestamp;
- pack generation timestamp where available;
- schema version;
- publication model `continuous_main`;
- relevant digests.

## Safety and scope

OpenVA records public vendor-published source references. It does not approve, certify, score, rank, recommend, or determine whether a vendor is compliant, secure, suitable, or low risk.

Do not upload private agreements, SOC reports, credentials, customer evidence, or confidential vendor inventories to any third-party service. The OpenVA browser resolver does not need them.
